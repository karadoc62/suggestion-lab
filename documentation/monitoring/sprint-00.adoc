== Initialisation du projet

Le Sprint 0 est un peu particulier. Dans certaines équipes Scrum strictes, on évite même cette appellation, mais elle est très courante en entreprise pour préparer le socle technique.

== Objectif du sprint

Disposer d'un dépôt Git propre et documenté permettant de commencer le développement de Suggestion Lab.

== US-001 — Initialiser le dépôt
=== User Story

En tant que développeur, je veux disposer d'un dépôt structuré afin de pouvoir développer indépendamment le client, le serveur et la documentation.

== US-002 - Préparer l'environnement Java / Gradle

En tant que développeur,
je veux disposer d'un environnement Java/Gradle reproductible
afin de pouvoir construire le serveur de Suggestion Lab.

=== Critères d'acceptation

[cols="1,3", options="header"]
|===
| AC1 | Le JDK utilisé est identifié.
| AC2 | Gradle est utilisable via le Wrapper.
| AC3 | Le projet Gradle reconnaît le module `server`.
| AC4 | Une classe Java simple peut être compilée.
| AC5 | La commande `./gradlew build` fonctionne.
|===


=== Tâches

[cols="3,1", options="header"]
|===
| Tâche | État

| Identifier la version du JDK
| ✅

| ✅

| ✅

| Configurer le module server
| ✅

| Compiler une première classe Java
| ✅

| Vérifier le build
| ✅
|===


== US-003 : préparer le déploiement WildFly

En tant que développeur,
je veux pouvoir produire et déployer une application web Java
afin d'exécuter le serveur Suggestion Lab avec WildFly.

Critère	Résultat attendu
AC1	Le serveur produit un fichier .war
AC2	WildFly peut être démarré localement
AC3	Le WAR peut être déployé dans WildFly
AC4	WildFly détecte correctement l'application
AC5	Le déploiement apparaît sans erreur dans les logs
